# 扩展代码库

仅在本次需要复用、编写或维护扩展代码时读取；普通协议不默认加载这些实现。源码先按能力分类，设备专属类集中在该设备入口，类和函数均可收录；不因目录存在而增加实验动作或推定实际装机。

生成涉及这些设备的协议时直接取用对应设备单文件，不要求AI手动拼接内部类或兄弟包；在protocol中完整内嵌模块实现，再写本次实验入口。USB初始化由每个完整模块内部处理，不作为普通协议参数或默认询问项；倾斜默认115200/8N1不据同芯片自动推广到正压设备，具体配置按各自源代码维护。

源码为实现和核对依据，接口说明分别见[倾斜API与加载](api-module-tilt.md)、[正压API与创建](api-module-positive-pressure.md)、[Riser辅助类](api-riser.md)；本入口不再复制签名。新增能力有实际实现后再增加分类，不提前建立空目录或虚构接口。协议结构、依赖与交付继续按[结构与依赖](api-types.md#依赖与执行边界)处理；上述入口已消除技能内包依赖，客户脚本不引用技能目录。运行环境依赖按各自能力核对，不因生成单文件而免除。

## 分层与扩充

- 通讯层负责连接、字节读写及资源生命周期；设备层负责其实际指令、编码、响应、状态与动作语义；专属几何及辅助状态与该设备集中维护，已有实际跨设备用途的实现再独立复用。设备业务不反向写入通讯层。
- 整合DIY或其他第三方设备时，可复用与真实接口和配置匹配的通讯实现，再根据提供的设备协议、源码或已核对的交互证据编写设备类。未提供的命令、帧格式、状态码或功能明确列为缺口，不凭接口类型猜补。
- 共用帧协议须另行核对后再提取；通讯连接成功、芯片型号匹配或某个设备类可用，均不构成其他设备型号或能力验证。
- 通讯层保留帧外的字节传输及资源完整性；设备层保留其帧校验、有效状态、动作结果及超时处理。实验策略、默认安装和洗板等流程约束归相应规则或模块资料，不塞入通用源码。
- 没有独立硬件指令、只组合SDK操作的通用辅助类归helpers；按实际用途新增，不登记为设备或官方模块，不把辅助库存等同于实物完整建模。
