# 耗材辅助：普通槽位叠板（Riser，非设备模块）

查用前应用[统一安装核验](installation-core.md#统一安装核验)；这里只维护本对象的承载表达、案例配置及具体证据缺口。
来源：用户Riser.py，SHA-256 ed4697668b4bf98b7032dc91631d1ca9fc9b3ba8ec9afaafc9fb033592628780；接口/状态和使用示例见api-riser.md。它是顶部逐板取出的软件辅助类，不是官方Flex Stacker，也不表示安装了opentrons_flex_deck_riser。
物理关系：本次实际普通槽位夹具/支撑 -> 同类耗材的真实上下层堆叠；同层竞争与上下适配按统一核验。SDK只登记当前最上层板的普通槽位代理，其他板及整体高度仍在物理账本保留，不能因代理取走或尚未重载就将剩余堆叠区域当作实物空位。
案例配置：原附件在C4登记opentrons_96_wellplate_200ul_pcr_full_skirt，quantity=5、层间高度增量13mm、首层额外高度0，先后搬至C2和D2。这些是原程序取值，不是通用默认或已验证组合；该板维护定义v4的stackLimit见[官方板盖与堆叠条目](installation-official-upper.md#六板盖同类堆叠及其他父层关系保持原始字段语义)，原5层不能据程序可执行就视为满足该定义。实际板型/版本、堆叠数量、相邻板参考面增量、整体高度及抓手路径按本次安装核对，不把重叠量直接作为高度增量。
占位与坐标：取完库存不表示已移走底座/夹具，真实支撑仍按其实物属性占位。取板Z补偿不改变官方耗材坐标或整叠障碍模型；底座高度也不能与已含支撑高度的定义重复叠加。目标drop_offset只处理目标侧抓手落板补偿，不建立第三方模块的完整绑定或安装关系。示例使用第4列仍按其普通暂存区域、API与deck configuration条件核对。
