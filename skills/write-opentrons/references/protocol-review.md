# 生成后的框架逻辑审查

从零生成完整脚本默认执行全量审查；修改已有脚本按下方变更范围选择检查，不因重新交付完整文件就重跑全量审查。它是按本技能规则对代码执行路径的静态状态推演，不是运行官方模拟器，不是自建完整机器人执行器。语法检查是另一项基础检查；官方模拟按下方环境检查按需执行，可用时作为补充，不替代本审查。框架审查通过不能推导官方模拟100%通过，更不能推导实机无碰撞。

## 按变更影响选择审查范围

|变更|默认处理|
|---|---|
|从零生成、整体重写，或用户明确要求全面审查|按本文件执行完整状态推演|
|注释、说明、显示标签等已确认不改变执行行为的编辑|核对编辑正确即可，不启动框架逻辑审查|
|单个流速、温度、等待等影响范围清楚的参数|核对实际覆盖位置、类型/边界及直接依赖；无进一步影响时到此结束，不做全流程推演|
|液量、次数、布局、枪头/喷嘴、模式、动作顺序或分支变化|按受影响状态局部推演，追到下游依赖消除或与可信既有状态一致；确实影响广泛时才扩大到全量|

按影响而不是改了几行判断：一行体积变化可能影响容量、液面、push_out与后续混匀，一行温度变化可能改变可达性和等待条件；不要自动把所有参数修改升级为全量审查。
既有代码已审查且未改动的部分复用结论，不反复读取或重新计算。既有代码没有可信审查记录时仍可完成明确的小改，但只对本次修改范围给结论，不补写整个脚本已通过；发现具体关联问题才扩展检查。用户明确指定审查范围或本次不审查时遵从，并如实标注，不制造额外审批。
首次审查发现问题属于正常迭代：修正后只复查受影响路径及下游，不每轮从头重审；问题消除且状态衔接明确后停止，不为追求形式重复检查。

## 规则唯一来源

用户术语按operations映射：不机械追问唯一可映射模块的GEN，不把省略代际解释为自动升级；垃圾处理核对实物类型与位置，D3不能单独消歧，明确类型与位置无冲突时不重复问。24孔温控铝块按installation已列组合一次load_labware，不捏造独立24孔adapter或重复计入管/铝块高度；通用管架和相近管型不能替代准确组合。

官方耗材按catalog核对检索范围、实物身份、定义版本和来源；常用项未命中不误判为不支持，发布索引命中不替代目标软件、实际模型或安装关系证据。网络受阻与本快照无匹配分别记录，不将未完成查找写成官方无定义或已完成验证。

## 协议结构与依赖

从零生成、整体重写或结构/依赖变化时按api-types“协议组成与骨架/依赖与执行边界”核对公开导入、metadata与唯一apiLevel声明、Flex requirements、单参数run入口及需要时的add_parameters及其定义上下文。普通协议不混入手动执行run/自建上下文，内部源码节选不复制为客户依赖。核对实际技能版本、用户覆盖、审查/模拟范围和未决项，不能照抄模板状态；模板阻断或空段不能冒充完成实验，删去阻断也不证明完整。外部文件、第三方包和生成工具依赖须对应实际交付及环境证据。模板、分隔线或可选区块本身不是审查硬条件；参数名/可选类型注解、合法辅助函数/类、静态数据位置、章节次序或不含动作的教学骨架不因不同于模板外观而误报；局部修改沿用原范围，不借结构模板强制全量复审。

## 沿路径逐步审阅

1. 按operations的集中描述及方案迭代流程，核对解释与当前用户意图、补齐项及实际动作一致，遗漏/缺陷及建议有依据；核对配置来自用户提供/确认、同设备有效档案、既有协议、已展示推荐的补齐或授权代选；使用历史档案时核对来源、设备/项目、本次回显确认及新旧差异，不能把保存成功当实机状态永远不变，并核对整合方案的技术可行性，不能以用户确认为硬件/API限制的豁免；未展示、未授权且无依据的项保留未决，推荐装机条件不当成实机已确认。实际硬件确认须能对应本次对话中的有效确认依据，不能由信息齐全、代码技术检查通过或仅授权布局反推；依据未取得时按operations保留待确认范围，不标完整流程通过。再建立本次状态：耗材位置与占用、孔内液量、枪头与喷嘴/盒消耗、枪头内液体/空气及容量、尖端位置、活塞准备与模式、模块盖/锁扣、震荡、各温控目标/到达与并发任务。区分已知、未知和执行中，不假定开局状态。
2. 逐条读取实际执行命令：检查前置条件→根据成功执行更新受影响状态→检查后续依赖。move/吸排动态终点以及模块命令附带的归位都可能改变位置；不要只追踪move_to。
3. 若50µL移液器启用探测，按operations核对探测后top(2)清膜、容量/模式、清膜前准备和跟踪影响。按operations核对入液/退出speed是否匹配液体类别及实际枪头规格（或明确覆盖），不只核对数值在旧范围内。等待按用户覆盖优先查询，核对水相实际枪头容量、源/目标实际入液后的submerge、每次吸排后的after；原位混匀不重复入液等待，0秒不生成。检查新头首次吸液的显式准备，以及已准备且无新事件时是否重复准备；跨阶段/源端与目标端的移动速度按实际接触液体分别核对，不因模板共用变量而略过差异。同步核对所有适用规则：接口类型和版本、堆叠与占位、体积守恒/容量/空气与尾液、取弃复用、进出孔/跨孔/沿壁、流速/等待阶段、push_out/准备/模式、模块装载/运行/收尾。只查涉及的规则，避免重新推导已知参数。
枪头补给命中时，按operations核对参数分支下的需求/可用取头组数、开场备盒提示、耗尽前暂停，以及更换后占位/绑定/可用状态仅更新对应盒；库存足够不应触发补给暂停。
深管/高液面风险命中时，核对operations的长度粗筛使用本次最深下探位置及匹配枪头定义、生成前确认已完成，代码及聊天交付与已确认的位置/范围一致；不得用默认bottom或液面探测掩盖未决机械下探限制。
液面跟随/体积换算命中时，核对实际定义及参与孔的有效模型引用、模型内容与本次体积范围，结合初始化和逐步账本；名称在官方清单或成品库不替代该核对。已有适用记录复用，缺模型/引用失效时按custom-labware保留缺口或采用明确选择的位置方案；固定已知坐标间移动不额外要求模型。
自定义定义命中时，对照实际输入/尺寸及所选交付方式；分离交付含匹配JSON与导入说明，内嵌版含完整定义且不依赖客户电脑/技能路径。模拟使用同一份定义，不把schema通过当实机验证。
沿壁路径命中时，核对实际耗材孔尺寸/形状/深度、目标高度截面与枪头间隙是否支持所选偏移及整段路径；区分移动与液体操作，检查后者是否改变退出起点。

储液槽部分喷嘴命中时，按reservoir-partial-nozzles.md检查已确认策略、定义/布局与Y偏移依据，以及top/吸排/终点/退出位置的一致性；用户选官方默认时不误报缺少偏移。

分段排空按operations逐项核对：原push_out资格、型号/枪头及严格阈值、两段体积和流速（含dry_run）、中间等待不叠加、末段正常等待、F−T/F的孔内总量、两段位置连续且不重返底部、只有末段非零push_out。混匀N=1和末轮均覆盖；未触发时不得强拆。

4. 条件分支按可达路径分别推演；合流仅合并一致状态，不一致的保留分支条件或标未知。循环检查首轮、普通轮、末轮及相邻轮衔接；参数化次数/体积检查允许边界和相应不变量，不必枚举所有样本数。dry_run、return_tips、预铺/换头/末孔移除等组合不能只检查默认值路径。按rates.md核对dry_run水相流速选择覆盖所有吸排动作及混匀实际体积，正常分支保留原液体流速；不得仅检查开关存在。
体积参数/CSV命中时，按rates的“可变体积与运行时输入”对照允许域与实际方案：选择改变后转移、M/S、分段体积、F−T/F及对应速率同步；检查容量截断与分段阈值两侧，以及不支持值在首个取头/移液前被拒绝。运行时CSV应检查全表，分析占位或默认参数通过不代表所有输入可用；次数变化但动作体积不变时不要求重复查率。
5. pause/人工补液/换板/换头后，只更新或失效实际可能改变的状态；并发Task开始不等于完成，目标已设不等于温度/转速已达，不把等待任务结束当自动停用。
长孵育按operations核对正式/dry_run所选总时长、分段合计、末段余时及提示分母一致，模块hold/到温/Task等待保持原语义；核对实际行为，不要求使用示例的循环写法或变量名。
6. 正常结束检查液体/枪头归宿、各模块停止或明确保持目标、盖/锁扣预期、未完成任务；将所得终态按下方“事实与交付一致性”对照用户目标。区分正常完成路径与中止，报告真正不能确定的项。

## 无意义动作审查

把重复开关、重复准备、重复到同位置、重复等待标为候选，而不是文本命中就删除。例：open_lid→没有改变盖状态的步骤→open_lid；若同一模块盖已知打开且无外部干预/强制确认要求，后一条可去除。不同模块、不同分支、状态未知或API要求首次确认时不能删除。
删除前证明前置条件仍满足、状态及流程结果不变、没有丢掉真实等待或必要避碰；删除后只重推受影响步骤及其下游。不能靠省略API要求的互锁/避碰来提速。不要为了消除所有未知而生成每步都读硬件状态或反复开关的代码。

## 环境检查与官方模拟

- 先按api-versions完成机器人支持范围→目标API选择→当前执行环境核对，检查代码使用的目标及最低接口版本一致。交付新生成、整体重写或改变执行行为的脚本前，复用或检查当前环境能否启动模拟入口；优先同一解释器的`python -m opentrons.simulate`，PATH的`opentrons_simulate`单独核实，通过实际帮助输出确认调用方式。SDK/模拟器上限不冒充机器人上限，帮助成功不当协议模拟通过。同一任务环境未变时复用可用性结果。纯注释/说明等非行为编辑可跳过；用户明确指定本次验证范围时遵从。
- 可执行时，对最终交付文件运行一次官方模拟，使用本次实际参数、CSV和自定义耗材等必要输入；按当前CLI支持的方式提供，不猜参数或静默替换输入。记录实际配置和覆盖范围，单次默认参数模拟不代表所有分支都运行过。
- 命令不存在、无法启动、版本不支持目标API或必要输入缺失时，说明具体原因及未运行/未完成状态，继续交付实际完成的技能审查结果；安装/升级仅在用户选择后按api-versions引导或执行；不修改目标API以迁就环境，不反复询问已拒绝的安装。
- 模拟已启动后发现协议错误，记录为模拟失败，不能归为环境不可用而跳过。按已确认需求修正后重跑最终文件；无法解决时明确保留失败与未决项，不标模拟通过。模拟后的执行代码若再修改，先重跑再引用通过结论。
- 聊天交付分别报告技能审查与官方模拟结果；模拟运行时注明可获得的模拟器版本和实际参数范围，未运行时简述原因。模拟通过不替代经验审查或实机验证。

## 运行文案核对

按operations的“源码说明与运行文案”核对参数顺序、耗材身份与简短用途，以及运行提示是否仅表达实际操作信息；经验解释可保留在源码注释/文件头。文案与参数实际行为一致，精简不能删除必要人工操作提示；纯文案修改只核对相关项，不因此启动全流程状态推演。
按operations核对内部硬件判定与用户展示是否分开、经验建议是否命中本次场景且未被自动加入动作；不要求每份交付都出现内部解释或经验提示。

## 事实与交付一致性

复用上面的执行路径账本，对最终代码、用户目标、文件头/注释、运行提示及聊天交付作同一次对照，不另造平行计算流程。只记录本次适用项；数值相同的孔/列合并，已有有效核算不重做。

|检查对象|可核对的结果与判定|
|---|---|
|最终实验结果|从实际循环/分支核算到最后一次移液，列各孔/列最终体积及浓度关系；混匀时液量与后续转出后的终量分别使用。与用户要求比较，不一致时定位孔位、目标值与实际值；浓度依赖混合均匀时标为理想计算，不据此承诺实测准确度。|
|供液、容量与归宿|核对各源需求、过程最小/峰值液量、废液及末孔例外；多喷嘴共享源按激活通道合计，建议余量与标签用量分开。容量或位置能容纳不等于已验证能可靠吸液。|
|枪头|按每段实际取头次数、喷嘴数及复用/末孔移除路径算组数与支数；与盒内可执行组数、补给及交付统计比较，不仅算总支数。|
|配置与参数依据|对照用户指定/推荐补齐/默认/推导的来源及已读资料、查询输出；确认型号、滤芯、液体、动作体积、流速/等待与代码匹配，事实结论有对应证据。|
|验证声明|对照实际记录中的对象（最终文件或副本）、API/工具版本、参数/分支、检查方法和结果；文件头与聊天使用相同范围。工具未运行记未运行，失败记失败；副本结果只归副本。数值核算、语法、状态推演、官方模拟和实机分别报告。|

记录可为当前工具输出或精简工作账本，不强制额外交付文件、逐步长表或穷举所有参数组合。以边界和不变量覆盖参数范围时据实描述；声称“运行了N个组合”时应有对应输入与结果，不能把推演覆盖范围写成N次实际执行。发现文案与代码不一致时先按用户目标判断修改哪一方，不为匹配说明擅改已确认流程。

结论随对照结果产生：适用项一致且关键状态有依据时为“通过（所列范围）”；存在确定差异时列问题，未知影响哪项就保留哪项未决。用户明确仅做条件方案时可按授权推荐所需配置，但不冒充真实装机已确认；面向实机生成仍按operations完成硬件回显确认，特殊条件未核对时注明影响。模拟未运行不抹去已完成的静态核对，也不升级为实机可执行保证。

## 交付记录

按operations在聊天交付关键孔参数摘要，逐项对照最终代码，包含流速与移动速度的不同单位、起终点及适用分支；小改只核对受影响项。检查实际要发送的聊天正文：只有附件链接或“详见文件”不满足此项；缺失时补紧凑摘要，不重复整份报告。

明确分别记录：框架逻辑审查（覆盖的分支与未决项）、语法检查（实际执行与否）、官方模拟（未运行/通过/失败）、实机验证（若无则未做）。通常给出简短结果，不倾倒逐条内部账本；发现修正可简述如“去除重复开盖，保留首次关闭确认”。用户要求详细审阅时再列步骤状态表。

## 标识与审查结论必须对应

使用技能标识只证明声明了所用版本，不替代审查。完成代码后实际读取适用规则、推演相应路径并处理发现的问题，才能给出审查结论；不能从模板来源、注释或语法通过反推经验合规。

完整审查交付提供紧凑审查凭据：技能名/版本；本次适用规则与已检查维度；关键分支和跨步骤状态覆盖；本次用户覆盖及理由；未决问题；结果。清楚区分“通过（在所列范围内）”“有未决项，未通过”和“未审查”，不声称绝对无遗漏。阻塞性未知状态/分支、缺失接口或未核对条件未解决时，不标通过。覆盖范围不适用的维度写不适用，不用空泛的“全部检查完成”。

脚本顶部保留技能版本、本次覆盖和实际审查状态的简短注释；交付说明同步给出相同结论。未实际审查不得写已审查；代码有实质修改后，重审受影响动作、分支和下游状态再更新结论。语法/官方模拟/实机结果单独列，不能用其中任一通过代替经验规则审查。

小改交付只简述“改了什么、核对了什么、是否重审”，无需完整审查表。未重审可标“本次仅参数核对/未进行全量复审”；不沿用旧的全量通过字样暗示修改后的全部代码已重新审查。历史审查记录可保留并注明版本/范围，纯文案修改不强制改写脚本审查头。
