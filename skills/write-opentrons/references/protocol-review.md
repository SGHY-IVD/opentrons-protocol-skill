# 生成后的框架逻辑审查

本审查按技能规则静态推演代码执行路径，与数值核算、语法检查、官方模拟和实机验证分别记录。框架通过不保证官方模拟通过；两者均不证明实机无碰撞，模拟不能替代本审查。完整生成默认全量审查，既有协议按影响选范围；重交完整文件不自动扩大范围。

## 按变更影响选择审查范围

|变更|默认处理|
|---|---|
|从零生成、整体重写，或用户要求全面审查|完整状态推演|
|已确认不改变行为的注释、说明、显示标签|只核对编辑正确|
|影响清楚的单个流速、温度、等待等参数|核对覆盖位置、类型/边界和直接依赖；影响消除即停止|
|液量、次数、布局、枪头/喷嘴、模式、顺序或分支变化|局部推演至下游依赖消除或与可信既有状态一致；影响广泛才扩大范围|

按影响判断，不能凭改动行数或“参数修改”直接决定全量与否。复用未改且可信的既有结论；无可信全量记录仍可做明确小改，只对实际范围给结论，发现关联问题才扩展。尊重用户明确范围或不审查要求，如实标注，不新增审批。修正问题后只复查受影响路径及下游；状态衔接明确、问题消除即停止，不逐轮从头重审。语法检查按改动需要执行。

## 沿路径逐步审阅

1. 核对方案解释、补齐项、代码和当前意图一致，配置/建议有依据且技术可行。配置可来自本次提供/确认、有效设备档案、既有协议、已展示推荐或授权代选；历史档案须核对来源、设备/项目、本次回显确认与差异，保存成功不证明装机永不变。真实硬件确认必须有本次有效对话依据，不能由信息齐全、技术检查、布局授权或推荐配置反推；用户确认也不豁免硬件/API限制。命中[编写前回显](protocol-interaction.md#编写前回显)时，核对对话中的最新方案回显及其后的用户确认均早于编写，并与交付代码一致。未授权或无依据项保留未决，缺适用确认不标完整流程通过。
2. 建立初始账本：位置/占用、逐孔液量、枪头/喷嘴/盒消耗、头内液体/空气与容量、尖端位置、活塞准备/模式、模块盖/锁扣、震荡、温控目标/到达和未完成Task；区分已知、未知、执行中。逐条检查实际命令前置→成功后更新受影响状态→检查后续依赖；移动、吸排动态终点及模块附带归位都可能改变位置，不能只追踪move_to。
3. 按下表触发相关规则，检查所得结论与实际状态；完整生成覆盖基础维度与适用组合条件，局部修改沿影响展开。复用已核实参数，只读本次涉及条目，不重新推导既有事实；模块和经验仅取命中设备/动作的相关章节。
4. 分支按可达路径分别推演；合流只合并一致状态，不一致保留条件或记未知。循环检查首轮、普通轮、末轮及相邻衔接；参数范围用允许边界与不变量覆盖，不必穷举样本数。dry_run、return_tips、预铺/换头/末孔移除等实际组合不能只查默认路径；试运行水相速率与正常液体分支分别核对，覆盖全部实际吸排和混匀体积，不能只查开关存在。
5. pause、补液、换板、换头后只更新/失效实际可能改变的状态。Task发出不等于完成，设定不等于到温/到速，等待完成不等于自动停用。[长孵育](operation-incubation.md#长孵育分段提示)的分支时长、分段合计/余时和提示须一致，模块hold、到温及Task等待保持原语义；不强制示例写法。
6. 核对正常终态的液体/枪头归宿、模块停止或明确保持目标、盖/锁扣和未完成任务，再与用户目标及交付对照；中止不等于正常收尾，真正未知项据实保留。

## 无意义动作审查

重复开关、准备、定位或等待只标候选。跨步骤检查同一对象的可信当前状态、外部干预、分支及API强制首次确认；状态未知、不同对象或必要互锁/避碰不能凭文本相似删除，也不为消除所有未知生成每步硬件查询或反复开关。

加液后同孔混匀按[连续原位混匀](operations.md#连续原位混匀枪头连续性--位置--模式准备需求)核对入口模式、加液前/后位置与实际量、首次吸液衔接、等待和准备事件；既有模式切换、明确覆盖及固定液面等必要准备分支仍保留，不能只查非零push_out链。

删除前须证明前置仍满足、状态/流程结果不变、真实等待和必要避碰未丢失；删除后仅重推受影响步骤及下游。

## 环境检查与官方模拟

- 先按[版本索引](api-versions.md)核对机器人支持→目标API→当前环境及接口最低版本。新建、重写或行为改变的脚本交付前检查/复用当前模拟入口可用性；优先同一解释器的`python -m opentrons.simulate`，PATH的`opentrons_simulate`单独核实，用实际帮助确认调用方式。SDK上限不冒充机器人上限，帮助成功不等于模拟通过；环境未变可复用，非行为编辑可跳过，用户指定范围优先。
- 可用时对最终交付文件运行一次官方模拟，按实际CLI提供本次参数、CSV、自定义定义等必要输入，不猜用法或静默替换。记录可得的模拟器版本、输入及覆盖；默认一次不代表全部分支。
- 入口不存在/无法启动、目标版本不支持或必要输入缺失，说明具体原因及未运行/未完成，仍交付实际完成的技能审查。安装/升级仅经用户选择按版本索引处理，不迁就环境改目标API，不反复询问已拒安装。
- 已启动后协议错误记失败，不能改称环境不可用；按确认需求修复后重跑最终文件，不能解决保留失败/未决。模拟后执行代码有改动，重跑后才能引用通过。
- 聊天分别报告技能审查与模拟结果；模拟未运行写原因，模拟通过不替代经验审查或实机验证。

## 交付记录

按[交付规则](protocol-output.md#技能标识与交付顺序)对照最终代码，核对交付正文回显的实际布局、关键耗材和流程。[参数摘要](protocol-output.md#聊天交付的关键孔参数摘要)给关键动作体积、吸/排流速（µL/s）、起终高度/路径、进退速度（mm/s）和适用分支，可合并同值。未知运行参数/CSV按该规则给支持域、计算依据和明确示例，不虚填实际值，小改只查受影响项。发送前只看正文不看附件：上述关键信息若只能在附件、账本或进度消息找到，补齐正文；这是交付说明检查，不推翻已完成技术结论。

分别记录框架审查范围/分支/未决、语法实际执行与否、官方模拟未运行/通过/失败及实机验证（无则未做）。通常短报结果和必要修正，详细状态表仅用户需要时给出。

## 标识与审查结论必须对应

技能标识只声明所用版本。实际读适用规则、推演路径并处理发现问题后才给结论；模板来源、注释或语法通过不能反推经验合规。适用项一致、关键状态有据才标“通过（所列范围）”；确定差异列问题，未知保留对应未决，不声称绝对无遗漏。

完整审查凭据须含技能名/版本、适用规则与检查维度、关键分支/跨步状态、本次用户覆盖及理由、未决项和结果；区分通过、有未决项未通过、未审查，不适用维度明记不适用。阻塞未知状态/分支、缺接口或未核对条件未解决，不能标通过。

脚本头保留技能版本、覆盖和实际审查状态，聊天同步；实质修改后重审受影响动作/分支及下游再更新，不拿语法/模拟/实机替代。小改只说明修改、核对与是否重审，可注明仅参数核对/未全量复审，不沿用旧全量通过暗示全码复查；历史记录可注明版本/范围保留，纯文案编辑不强制改审查头。
