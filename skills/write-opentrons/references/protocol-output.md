# 协议源码、运行文案与交付

本文件维护源码说明、面向操作员的运行文案、默认测试参数和聊天交付。液量/动作/路径的权威规则见[操作规则](operations.md)及[场景策略](operation-scenarios.md)，参数声明与读取契约见[参数API](api-parameters-csv.md)；审查范围、凭据与结论见[协议审查](protocol-review.md)。

## 源码说明与运行文案

协议结构及骨架查阅按SKILL对应路由；可用简短分隔注释辅助阅读，例如 `# ---- 布局与设备加载 ----`。参数、布局、液体标签、执行及收尾等区块只作可选示例，名称、数量、位置、顺序及是否使用分隔线均不构成强制要求；按实际任务与既有规则组织，不为套模板新增动作或重排无关内容。顶层声明及可选数据/类位置见api-types。源码注释不自动转成protocol.comment运行日志。

Python源码的#注释面向脚本编写者：布局和实验程序设计在此简短说明该段用途，按需保留关键经验、设计理由、参数依据及特殊动作目的；提炼成与当前代码一致的说明，不复制讨论记录。技能版本、用户覆盖及真实审查标识按本文件“技能标识与交付顺序”保留。

完整新脚本保留文件头、职责分区及实际采用的场景策略三层必要源码说明：文件头沿用本文件的标识及[协议审查](protocol-review.md)的验证要求，按实际任务补充整体实验目的、关键前提、参数来源及必要的总体计算约定；加载、初始化、实验执行及收尾等职责在对应位置用简短标题区分；有较完整的场景组合时，标明实际策略名称，并就近简述采用目的、关键参数依据或本次覆盖原因，块上下可用简短分隔注释辅助识别。不存在对应内容的区块可省略，相关区块可按实际内容合并或调整；不要求固定名称、分隔样式、顺序或函数封装，小改只补涉及的说明，不为此重排已有脚本。
说明聚焦上层方案和策略，常规吸排液、移动、等待等原子命令不逐行复述API或通用规则；必要的特殊选择在所属策略块说明。参数公式写在相应定义/计算处，不将全部细节堆到文件头。策略名称用于识别实际行为，参考片段本身不成为规范来源；不把模板占位、内部路由清单或讨论过程复制进交付代码。

面向实验操作员的参数display_name/description/choices、耗材与液体展示标签、protocol.comment和pause提示，只描述实际用途、选项行为、装载要求、执行进度或需要操作者完成的动作，简洁且无歧义；默认操作员与脚本编写者是不同角色，即使由同一人承担，也不混用两类说明。protocol.comment通常只写“开始加样”“进入孵育”等简短阶段/进度提示；不把布局/程序设计说明、上下文讨论或审查过程转成运行日志。是否展示按操作者实际需要判断，不因讨论过某项实现理由就自动新增提示或参数。必要的换盒、装载、确认等操作提示仍保留。

耗材展示标签保留可识别的耗材类型/名称，按需追加括号内极简用途，优先不超过4个字/字符，例如“NEST 96孔深孔板（稀释）”；不只用“稀释板”替代耗材身份，不修改实际load_name。液体标签继续按[液体与体积账本](operations.md#液体与体积账本)的实际用途命名。

运行参数按最常调整的优先、同用途相邻排序，并按该顺序声明：通常先放枪头起始位置/取用顺序、样本数/样本板数等运行配置，再放移液量、混匀次数/体积等实验参数，随后放高度/偏移等细节配置；dry_run、return_tips默认依次放在最后。实际使用频率可调整业务参数的先后；不存在的类别直接跳过，不为排序新增参数。仅改展示或顺序时保留变量名、默认值、choices内部值和实际执行逻辑。

## 二选一运行参数的显示与内部值

布尔含义或只有两种选择的运行参数，默认使用choices选项，不使用add_bool开关UI；这是用户界面偏好，不表示官方不支持add_bool。优先add_str配稳定的字符串value；已有整数语义可用add_int配choices，不同时传minimum/maximum。选项display_name写明确行为，如“正式运行 / 用水试运行”“丢弃枪头 / 返回枪头”，避免只写“开/关”或缺少上下文的“是/否”。默认值必须属于选项并保留原业务默认。

读取参数后可显式比较转为bool，或直接按枚举值分支；禁止bool("false")、bool("off")或直接if非空字符串，因为两种选项都可能为真。显示选择不改变原有返回枪头、dry_run等规则。用户明确要求保留开关时按本次覆盖；修改既有脚本的参数类型时同步所有读取/判断，并说明旧参数预设可能需重新选择，不为无关小改自动迁移全部参数。

## 测试运行参数

每个新脚本默认添加dry_run和return_tips二选一choice运行参数，两者独立，内部布尔语义默认False（正式运行、丢弃枪头）。return_tips控制去向；dry_run默认以水替代试剂，吸排液流速按rates.md的“dry_run流速选择”统一切换到水相，并缩短长孵育/减少混匀，保持至少一次混匀及最终排净结构，正式复用另处理。通用开关不是部分取头回头授权。实机空跑与软件模拟不同，后者不消耗实体头。

每个实际启用分支按[rates](rates.md#dry_run流速选择)确定正常/用水所需的维护配置；定值、映射或必要计算按[参数化指引](parameter-planning.md)选择。

## 液体类别展示

聊天交付只突出采用organic/glycerol的液体和具体行为：写清试剂或混合液、对应步骤/吸液/排液/混匀、采用类别，以及简短依据（用户指定或助手推断）。同液体同类别的连续操作合并说明；混合后类别改变时按实际步骤区分，不把源试剂分类机械用于整段流程。聊天中水相不逐项列举，全为水相时省略液体类型说明；用户要求完整明细时再展开。此精简仅限聊天交付：代码注释可完整列出全部液体类别（含水相）、用途及依据，不因聊天省略而删除代码内明细；也不强制每条命令重复分类注释。参数来源和明确覆盖仍按交付规范说明，可合并表达，避免重复。

## 技能标识与交付顺序

实际读取并应用技能后，脚本顶部添加技能write-opentrons、实际规则版本、本次用户覆盖项及实际框架审查状态的简短注释，完整生成交付同步标识；读取失败不得贴已使用标识。标识不替代审查：全量审查的紧凑凭据、结论范围、小改说明和各验证结果的区分按[协议审查](protocol-review.md#标识与审查结论必须对应)执行；未运行模拟不得称通过。

最终聊天正文依次给出协议、关键操作参数摘要、验证与未决项。完整生成交付说明参数来源（技能经验/已收录官方数据或API默认/本次覆盖/未覆盖）、容量截断、特例、实际验证结果和真正未解决项；聊天及源码液体类别按[液体类别展示](#液体类别展示)处理。对按用量初始化的试剂源孔，另按[用量标签与实际装载建议](operations.md#用量标签与实际装载建议)给出标识用量与实际额外装载建议。可独立完成的先完成，只集中询问阻塞项。

## 聊天交付的关键孔参数摘要

完整脚本交付时，在聊天正文附紧凑参数表，不以文件内注释替代。按关键源孔、目标孔及操作阶段列：孔位/用途、单通道吸排体积、吸液/排液flow_rate（µL/s）、吸液位置、排液起点及终点、入液/退出move_to速度（mm/s）、push_out；存在关键等待时同时列阶段和秒数。液体类别信息按[液体类别展示](#液体类别展示)列示，可并入此表。

相同参数的孔/列合并，不逐孔重复；已知体积或已取得的真实CSV按实际动作列值，混匀M/S不同则区分。连续参数或运行时CSV在交付时尚无实际取值的，列协议支持的输入域、影响流速/位置的分支或计算关系，并把选取的代表值标为“示例”，不称为实际运行值或已核对该CSV。动态液面写清meniscus偏移和dynamic含义；体积换算终点写清使用的最终孔内总量，不伪造固定高度。dry_run有不同流速时标明对应值或清楚的分支映射。摘要必须与实际交付代码一致；局部修改仅列受影响关键参数，不重复全流程。重要未决项按[主动确认规则](protocol-interaction.md#主动确认按影响筛选)另在聊天提出，不因已列参数表视为已确认。

深管/高液面等经生成前确认的关键处理，交付时简述“涉及耗材/操作、确认采用的位置或下探限制、是否启用探测/液面跟随及其范围”，与代码对应；不把用户确认或源码核对表述成实机碰撞验证。仅说明本次命中的处理，不扩展成通用风险清单。

经验提示只在用户反馈枪头内明显残液、尖端外壁挂滴，或明确讨论对应优化时触发，可在相关答复/交付末尾简短给出思路：需排净但内有残液时先核对排液量、流速和等待，必要时评估blow_out；外壁挂滴时评估耗材适用的touch_tip或已有沿壁方案。这里是建议，不自动加入代码；启用仍按[现有按需规则](operation-motion-special.md#按需touch_tip)检查位置、耗材适用性、液体归宿及后续活塞准备。不在实验开场或每次交付固定罗列功能，不重复推荐已采用的同一措施；内部判定依据、源码维护说明和讨论记录不转成面向操作者的提示。

已知有本次可用的设备连接、文件及本次检查已完成时，可按场景简短提示是否发送到该Flex并获取设备端分析结果，带上真实设备名和IP/地址；示例及授权复用见[设备连接与发送](flex-http.md)。不是固定交付项，不自动上传或开始实验；设备端分析与本地模拟分别记录。
