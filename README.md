# Opentrons Protocol Skill

**将实验需求、用户配置及已说明的推荐方案，转换为符合移液经验、可审阅的 Opentrons Flex Python 协议。**

[English](README.en.md) · [技能入口](skills/write-opentrons/SKILL.md) · [审查回归案例](skills/write-opentrons/assets/review-regression/maintenance.md)

这是一个社区维护的 AI Agent Skill，源于实际协议编写经验的持续整理。它把 API 参考、设备与耗材约束、移液规则、原子代码片段和审查流程组织成一个按需读取的知识包，让 AI 编写脚本时有明确依据。

本项目不是 Opentrons 官方项目，也不是独立运行的协议生成器、机器人驱动或模拟器。

## 适用场景

你提供实验目标、已有流程与实际设备信息。第一轮通过完整示例引导实际硬件及机器人软件版本，核对后回显配置、支持API和本次目标供你确认；第二轮在已确认配置上解释并迭代实验流程、耗材布局和动作逻辑。信息已给全时直接回显，不重复问答。AI使用本技能完成代码编写、修改及规则审查。例如：

- 根据 SOP 和已确定的布局生成完整 Flex 协议。
- 组装常规移液、手写混匀、一吸多分和梯度稀释流程。
- 加入液体标签、模块操作、抓手搬运、空跑与枪头复用参数。
- 检查容量、余液、活塞准备、移动路径、占位及模块状态。
- 修改已有协议，并根据改动影响选择局部或完整审查。
- 按需发现可连接的Flex、读取配置，并在用户授权后发送脚本及查看设备端分析。

本技能仅服务 **Opentrons Flex**，不提供OT-2协议或专属模块/API。跨机型共享且适用于Flex的接口、硬件及官方定义字段仍保留。

## Skill 是什么，如何使用？

Skill 是供 AI 助手读取的指令与资源包：`SKILL.md` 定义工作方式和资料路由，`references/` 提供规则与接口，`scripts/` 提供确定性的计算工具。它不需要训练模型，也不是把全部资料塞进一段提示词。

将本仓库中的 **整个 `skills/write-opentrons/` 文件夹**安装到所用 AI 客户端支持的技能目录，或通过其技能导入功能导入。不同客户端的安装入口和目录不同，请以客户端当前文档为准。保留目录结构，不要只复制 `SKILL.md`。

```bash
git clone https://github.com/SGHY-IVD/opentrons-protocol-skill.git
```

安装后，在对话中明确要求使用 `write-opentrons`，并提供实验流程和布局。如果客户端不支持原生 Skill，可让具备文件读取能力的助手读取 `skills/write-opentrons/SKILL.md`，再按其中路由读取资源；这不等同于完成原生安装。

技能执行流速、等待和回归辅助脚本需要 Python 3；这些辅助脚本及HTTP工具使用标准库。只有按需启用mDNS发现时需要Python 3.10+及独立的可选依赖；安装方式见[设备工具说明](skills/write-opentrons/references/flex-http.md)。运行生成的 Opentrons 协议还需要匹配的 Opentrons 环境。客户端需要能读取相关文件；无法执行查询工具或读取资料时，应报告缺口，不凭记忆补值。

核心技能资料目前主要为中文，可用中文或英文提出任务。本仓库提供中英文项目说明；尚未逐一验证所有支持 Skill 的客户端。

### 安装后的更新选择

无论手动复制/导入，还是把仓库链接交给智能体协助安装，安装后是否同步更新都由用户决定。默认按需手动同步；宿主支持后台任务时，可选择定期检查并提醒。自动同步还需要宿主具备技能更新能力并获得用户明确授权，频率和动作范围由用户选择。本仓库不附带自动更新器，具体能力取决于客户端。

协助安装的智能体应在安装完成后，一次性说明本地支持哪些更新方式，再由用户选择是否启用；用户未选择时保持手动，不阻塞安装。不支持后台任务时如实说明，不承诺自动执行。检查时可对照已安装版本/提交与仓库版本；更新时同步整个技能目录，复制/导入安装需相应替换或重新导入，并保留本地定制。这些安排属于安装和维护阶段，不加入技能运行流程，也不要求每次使用前联网检查。

## 开始一次任务

可直接向助手发送：

> 请使用 write-opentrons 技能，按下面的实验流程和 Flex 甲板布局编写 Python 协议。先识别真正影响执行的缺失信息；生成后按技能规则审查，并在交付时列出关键孔的体积、吸排液速度、高度、重要覆盖项和未决问题。
>
> 实验步骤：……  
> 移液器与枪头：……  
> 耗材 load name、模块与插槽：……  
> 各步转移体积、混匀与换头要求：……  
> 特殊液体、初始液量及其他覆盖项（如有）：……

不必提前填写所有参数，也不要求照模板填写。实际设备不清楚时，AI先示范如何描述移液器、模块/适配器、垃圾处理和拓展位，再核对并复述实际配置供你确认；硬件示例的省略项不能默认成已安装设备。之后用通俗完整的实验方案解释怎么做、为什么这样安排、有哪些遗漏及建议，供你自由修改。实验方案中未修改的部分可沿用已展示推荐；已确认硬件不随推荐改变。完整输入可直接回显整合方案，本任务内已有有效确认直接复用；无实质冲突且已明确要求生成时不另设固定批准轮次。未指定试剂初始液量时，按本次用量计算可视化标签，并另行提示实际额外装载建议。

机器人软件决定目标API，不再无条件套用文档基线2.30；高于维护范围时说明差异并建议已维护目标。随后只读检测当前执行环境，分别报告本地包版本、SDK上限和模拟入口；不将云环境当用户电脑，也不因本地模拟器旧而暗改协议。模拟环境缺失或不匹配时，助手说明本地模拟与测试的用途，并在用户同意且可操作时协助安装／升级和复测；拒绝后仍可编写并如实标记未模拟。硬件配置持久化也须用户同意及宿主能力支持；历史配置下次作为已知示例回显，请确认或只改差异，不直接认定本次实物未变。

交付应包含协议文件、实际使用的规则版本、关键操作参数和真实审查结果。标识本身不能替代审查；未运行官方模拟器不得声称模拟通过。

## 框架与特点

| 层次 | 内容 |
| --- | --- |
| 入口与路由 | 按任务读取相关资料，避免每次加载整个知识库 |
| API 与安装关系 | 维护的版本基线、调用参数、load name、堆叠和甲板约束 |
| 独立状态维度 | 液体账本、枪头、空间路径、活塞与模块状态 |
| 参数数据 | 吸排液流速、等待时间；区分经验覆盖与已收录官方数据 |
| 原子与流程参考 | 原子命令、保留液混匀、模式切换、梯度稀释等组合示例 |
| 审查与回归 | 沿执行路径推演状态；使用固定案例维护审查能力 |

默认用 `aspirate`、`dispense`、`move_to` 和显式循环组合，避免高级移液命令与过度封装。模板是组合参考，不能覆盖核心规则。API 和安装关系缺失时报告；已确定耗材的几何属性缺失时，可按技能指引查询官方 GitHub 定义。
